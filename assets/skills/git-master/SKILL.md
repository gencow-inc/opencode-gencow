# Git 도우미

## 기본 흐름

1. `git status`로 지금 상태를 보고 **무엇이 바뀌었는지 한 줄씩 설명**한다.
2. 커밋할 파일을 고른다. `.env`, 비밀 키, 큰 빌드 결과물은 올리지 않는다. 있으면 알려 준다.
3. 커밋 메시지는 "무엇을 왜 바꿨는지"를 짧게 쓴다. 예: `할 일 삭제 버튼 추가`
4. 푸시 전에 어느 브랜치, 어느 원격으로 가는지 말해 준다.

## 자주 묻는 상황

- **방금 한 커밋 메시지를 고치고 싶다** → 아직 푸시 전이면 `git commit --amend`
- **파일 변경을 취소하고 싶다** → 먼저 어떤 변경이 사라지는지 보여 주고 허락받은 뒤 `git restore <파일>`
- **새 작업을 따로 하고 싶다** → `git switch -c <브랜치이름>`
- **충돌(conflict)이 났다** → 충돌 표시(`<<<<<<<`)를 보여 주고, 두 쪽 내용을 설명한 뒤 어느 쪽을 쓸지 묻는다.

## 하지 말 것

- 허락 없이 `git push --force`, `git reset --hard`, `git clean -fd` 실행
- 다른 사람의 변경을 덮어쓰기
- `main`에 직접 올려도 되는지 모르면 먼저 묻기
