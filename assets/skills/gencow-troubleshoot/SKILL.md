# 오류 해결

## 순서

1. **오류 문장을 그대로 확인한다.** 오류 코드, 어느 단계(설치/빌드/실행/배포/DB)에서 났는지 찾는다.
2. **프로젝트 점검을 먼저 한다.** `gencow doctor` (읽기만 하는 진단). 고쳐 준다는 `--fix`는 바뀔 내용을 먼저 보여 주고 허락받은 뒤에만 쓴다.
3. **Gencow MCP의 오류 진단 도구** (MCP가 인증 오류를 내면 먼저 `opencode mcp auth gencow` 로 로그인하게 한다)에 오류 문장을 넣어 원인과 해결 방법을 찾는다. 버전이 의심되면 호환성 확인 도구도 쓴다.
4. **원인을 한두 문장으로 쉽게 설명**하고, 고칠 방법을 제안한다. 사용자가 이해한 뒤에 고친다.
5. **고친 뒤 같은 동작을 다시 해서** 정말 해결됐는지 확인한다.

## 원칙

- 추측으로 고치지 않는다. 증거(로그, 오류 코드, 문서)를 먼저 찾는다.
- 한 번에 하나만 바꾼다. 그래야 무엇이 효과였는지 안다.
- 오류 문장에 안내된 명령이 있으면 그것을 우선한다.
- 사용자가 고칠 수 없는 서비스 쪽 문제로 보이면, 그렇게 말하고 상태 확인 방법(`gencow deploy status`)과 기다릴 조건을 알려 준다. 사용자를 탓하지 않는다.
- DB 마이그레이션 오류에서 이미 적용된 마이그레이션 파일이나 내부 기록을 직접 고치게 하지 않는다.
- 비밀 값이 로그에 보이면 가리고 보여 준다.
