# 디버깅 순서

1. **증상을 한 문장으로 적는다.** "무엇을 했을 때, 무엇이 나와야 하는데, 실제로는 무엇이 나온다."
2. **재현한다.** 같은 증상을 다시 만들 수 있는 가장 짧은 방법을 찾는다. 재현이 안 되면 고치지 않는다.
3. **관찰한다.** 오류 메시지, 로그, 입력 값을 본다. 필요하면 확인용 출력(`console.log`)을 임시로 넣고, 끝나면 지운다.
4. **가설을 세우고 하나씩 검증한다.** "아마 A 때문일 것이다" → A를 확인하는 실험을 한다.
5. **원인이 확인된 뒤에만 고친다.** 증상만 가리는 임시 처방은 피한다.
6. **다시 재현해 해결을 확인한다.** 같은 문제가 다시 생기지 않게 테스트가 있으면 추가한다.

## 사용자에게

- 지금 어느 단계인지, 무엇을 확인 중인지 짧게 알려 준다.
- 모르는 것은 모른다고 말하고, 확인 방법을 제안한다.
- Gencow 관련 오류는 `gencow-troubleshoot` 스킬과 Gencow MCP를 함께 쓴다.
